# Story identifiers

Every story folder is created by `/story-spec` in `.agents/stories/`, and is named one of two ways:

- **From a GitHub issue:** `GH-<n>-<slug>`, e.g. `GH-45-add-csv-export`. `<n>` is the issue number, and `<slug>` is built from the issue title. Issue stories take no code.
- **Standalone:** `<code>-<slug>`, e.g. `k3f9-user-login`. `<code>` is 4 random lowercase letters and digits, generated by `/story-spec`. `<slug>` is built from the name `/story-spec` infers from the spec conversation.

**Kebab-case** means lowercase, spaces and underscores replaced by `-`, other punctuation removed.

A story's **id** is `GH-<n>` for an issue story, or `<code>` for a standalone story. `.agents/stories/` also holds `config.yml` (and may hold a `README.md`). Only folders are stories.

## Resolving an identifier

Every command that takes a `<story-id>` accepts:

- an issue id: `GH-45`, `gh-45` or `#45`
- a standalone code: `k3f9`
- the full folder name

Matching is case-insensitive, so `GH-45` and `gh-45` are the same story. Resolve the id in this order:

1. If no `<story-id>` was given, get one per **When the identifier is omitted**.
2. Normalize `#<n>` to `GH-<n>`.
3. If it matches a folder name in `.agents/stories/`, use that folder.
4. Otherwise, glob the folders `.agents/stories/<story-id>-*`.
5. If exactly one folder matches, use it. If more than one matches, stop, list them, and ask for the full folder name. If none matches, stop: "No story found for `<story-id>`."
6. Offer to switch to the story's branch per **Switching to the story's branch**. Never skip this step.

Commands refer to the resolved folder as `<feature-name>`.

## When the identifier is omitted

A command that takes a `<story-id>` and gets none picks the story in this order, stopping at the first source that gives one:

1. **The git branch.** Take the part of `git branch --show-current` after the last `/`. It names a story when, ignoring case, it is the story's id, or it starts with that id followed by `-`. For example, `feat/GH-45-csv-export` names `GH-45-add-csv-export`, but `GH-4-fix` doesn't. If more than one story matches, stop, list them, and ask for the full folder name.
2. **This session's last hand-off.** Take the `<id>` from the first line of the most recent story workflow hand-off in this conversation, which has the form `/story-<command> <id> <status>` (e.g. `/story-review GH-45 completed`), and use it as `<story-id>`.
3. **The user picks.** Ask, listing every story folder in `.agents/stories/` by its display id and the rest of its folder name. List standalone stories first, then issue stories. Wait for the reply:

   > "Which story? Reply with its id.
   >
   > These stories are available:
   >
   > - k3f9 user-login
   > - GH-45 add-csv-export"

   Use the reply as `<story-id>`. If `.agents/stories/` has no story folders, stop: "No stories yet. Run `/story-spec` to start one."

Never guess from folder names or `LOGS.md` timestamps.

Before doing anything else, tell the user which story was picked and why:

> "Using `<id>` from branch `<branch>`." or "Using `<id>` from this session."

## Switching to the story's branch

Once a story is resolved (from an id given with the command, or from any source in **When the identifier is omitted**), skip this section if the current branch already names it, by the rule in **The git branch**. Otherwise, look for local branches (`git branch --format='%(refname:short)'`) that name the story, by the same rule:

- **One branch:** ask "Story `<id>` has branch `<branch>`. Switch to it? (yes / no)"
- **More than one:** list them and ask which one to switch to, if any.
- **None:** offer to create one, per **Creating the story's branch**.
- **The user says no:** stay on the current branch.

Before switching, run `git status --porcelain`. If it shows uncommitted changes, don't switch. Stop:

> "You have uncommitted changes on `<current-branch>`. Commit or stash them, then run `/story-<command> <id>` again."

Otherwise, run `git switch <branch>` and go on with the command.

## Creating the story's branch

If `git status --porcelain` shows uncommitted changes, don't offer to create a branch; stay on the current branch. Otherwise:

1. Get the base: `git symbolic-ref --short refs/remotes/origin/HEAD`.
2. Ask: "Story `<id>` has no branch. Create `<feature-name>` from `<base>`? (yes / no, or reply with another name or base)". If step 1 failed, ask instead: "Story `<id>` has no branch. Create `<feature-name>`? Reply with the existing branch to base it on (e.g. `main`), or no."
3. If the user replies with another name, it must start with the story's id, by the rule in **The git branch**. For example, `feat/GH-45-csv` is accepted, but `csv-export` isn't. If it doesn't start with the id, say so and ask again.
4. `<base-branch>` is `<base>` without a leading `origin/`. Run `git fetch origin <base-branch>`. If the fetch fails, show its error and ask: "Couldn't fetch `<base-branch>`. Create `<name>` from the last fetched `origin/<base-branch>`, which may be behind? (yes / no)". On no, stop.
5. Run `git switch --no-track -c <name> origin/<base-branch>` and go on with the command. If the switch fails, stop and show its error.

## Displaying an identifier

In output shown to the user (hand-offs, `Next:` lines, `/story-resume`'s summary), show only the story's **display id**, written `<id>`:

- A standalone story shows only its code, e.g. `/story-plan k3f9`.
- An issue story shows `GH-<n>` as written in its folder name, e.g. `/story-plan GH-45`.

The exception is file paths the user is meant to open: those use the full folder name.
